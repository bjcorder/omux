# Changelog

All notable changes to omux.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project adheres loosely to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

First end-to-end release of omux: a Linux-native multi-terminal
workspace where panes light up when an AI coding agent finishes a
turn or asks for input. Targets GTK 4.18+, libadwaita 1.7+,
WebKitGTK 6.0, VTE 4.

### Highlights

- **Recursive split layout** with per-leaf tabs — h/v splits
  (`Ctrl+Shift+D` / `Ctrl+Shift+E`), drag-resize from `gtk::Paned`,
  directional `Alt+Arrow` navigation, per-leaf `+` button for adding
  tabs or splitting without learning shortcuts, per-tab `×` close
  that collapses the leaf out of the tree when it empties.
- **Multi-workspace state**, persistent in two layers. Each
  workspace's layout / running shells / scrollback / agent state /
  browser pages survive workspace switches (in-memory: one
  `PaneTree` kept alive per opened workspace) and full app restarts
  (on disk: TOML layout snapshot + SQLite k/v state). Resizable
  sidebar with width persisted across restarts and drag-reorder
  workspaces.
- **Embedded WebKitGTK browser pane** (`Ctrl+Shift+B`) with
  per-workspace `webkit6::NetworkSession` so cookies, local storage,
  and cache are scoped per-workspace.
- **Agent detection** built-in for Claude Code and Codex CLI, with a
  TOML manifest schema for user-defined agents. Detection polls
  `tcgetpgrp(pty_fd)` → `/proc/<pid>/comm` against manifest regexes
  every 500 ms.
- **Hook-routed notifications**: pane ring + tab badge + sidebar
  workspace badge, all cleared on pane focus. Hooks run the small
  `omux-hook` helper, which talks to omux over a Unix domain socket
  at `$XDG_RUNTIME_DIR/omux/control.sock`. Offline events buffer to
  `pending-events.jsonl` and replay on the next start.
- **Reversible Claude Code hook install**: first-run consent dialog
  merges `Stop` + `Notification` hooks into
  `~/.claude/settings.json` with a backup file alongside.
  `omux --uninstall-hooks` removes only the entries carrying the
  `_omux_managed: true` sentinel, so unrelated edits to the settings
  file (yours or Claude Code's) survive the uninstall.
- **PTY-output regex fallback** for harnesses without hooks
  (debounced 2 s, deduplicated by matched text). Configurable per
  agent manifest.
- **Right-click menus** on terminal panes (Copy / Paste / Clear /
  Split / New tab / Close tab) and sidebar workspaces (Rename /
  Pin / Delete).
- **Install + uninstall scripts** that drop binaries into
  `~/.local/bin` (or `/usr/local/bin` with `--system`), register a
  `.desktop` entry and SVG icon into XDG dirs, refresh
  `update-desktop-database` and `gtk-update-icon-cache`.

### Build + release infrastructure

- **CI workflow** (`.github/workflows/ci.yml`) running fmt, clippy,
  test, and workspace build on every PR and push to `main`. Uses an
  `archlinux:latest` container so GTK 4.18+ / WebKitGTK 6 / VTE 4
  are available (Ubuntu's GTK is 4.14).
- **Release workflow** (`.github/workflows/release.yml`) triggered
  by `v*` tag pushes. Builds
  `omux-X.Y.Z-x86_64-unknown-linux-gnu.tar.gz` (binaries +
  `.desktop` + icon + `install.sh` + LICENSE + README) and a
  `omux-X.Y.Z-source.tar.gz` via `git archive`. Computes SHA256
  sidecars, extracts release notes from this CHANGELOG.
- **SLSA Build Level 3 provenance** on every release artifact,
  generated by the official
  [`slsa-framework/slsa-github-generator`](https://github.com/slsa-framework/slsa-github-generator)
  reusable workflow. Sigstore-signed in-toto attestation
  (`omux-X.Y.Z.intoto.jsonl`), Rekor transparency-log entry.
  Verifiable end-to-end with `slsa-verifier` — see
  [`docs/VERIFYING.md`](./docs/VERIFYING.md).
- **`cargo-release` configuration** (`release.toml`) wired to a
  single-version-source workspace: one `cargo release patch|minor|
  major --execute` invocation bumps the version, rewrites this
  CHANGELOG's `[Unreleased]` heading, commits, tags `vX.Y.Z`, and
  pushes both. Pre-release hook runs `cargo test --workspace
  --locked` so a broken test halts the release before it gets a tag.
- **Release docs**: maintainer step-by-step at top-level
  [`RELEASING.md`](./RELEASING.md), consumer verification guide at
  [`docs/VERIFYING.md`](./docs/VERIFYING.md), security policy and
  threat model in [`SECURITY.md`](./SECURITY.md), conventional-commit
  guide in [`CONTRIBUTING.md`](./CONTRIBUTING.md).
- **`install.sh` runs from either a git checkout or an extracted
  release tarball** — it detects which layout it's in and either
  builds with `cargo build --release` or just copies the prebuilt
  binaries next to itself.

### Internal

- **52 automated tests** across two crates: SQLite migrations,
  agent manifest TOML parsing + regex compilation + match cases,
  `PaneStatus` state machine, hook installer idempotency + surgical
  uninstall, and 8 end-to-end tests for the `omux-hook ↔ Unix
  socket` wire contract (round-trip, env vs flag pane id,
  kebab-case kind, payload pass-through, all error paths, and the
  offline `pending-events.jsonl` fallback).
- **IPC moved from D-Bus to Unix domain socket** at phase D of M4.
  Lighter dependency stack and cleaner integration with glib's
  main-loop than `zbus`. Decision recorded in `omux/src/ipc/mod.rs`.
- **Terminal renderer swapped from libghostty to vte4-rs** at M0.
  libghostty has no standalone Linux library packaging yet
  (no `libghostty.so` in distro repos); vte4 is the documented
  design.md §13.1 escape hatch.
- **Multi-live `PaneTree` per workspace** — switching workspaces
  used to rebuild the target tree from snapshot every time,
  killing every running shell and resetting cwd. Workspaces now
  stay alive in a `HashMap<String, PaneTree>` for the lifetime of
  the app; switching is just a `gtk::Bin` child swap.
- **Capture-phase window shortcuts** — without this, VTE eats every
  `Ctrl+Shift+*` / `Ctrl+T` / `Ctrl+W` before the window-level
  `ShortcutController` sees them. Switched to `PropagationPhase::
  Capture`.
- **Clean shutdown** — `cleanup_runtime_state` is wired to both
  `Application::connect_shutdown` (normal close) and SIGINT/SIGTERM
  handlers, so the control socket is always removed.

### Known limitations

- **Drag-drop pin-boundary enforcement** during a sidebar drag is
  incomplete: basic reorder works, but pinned items aren't locked
  to the top mid-drag.
- **GUI verification checklist** (`docs/design.md` §9, mirrored to
  `PROGRESS.md`) requires a human at the keyboard for steps 2–6
  and 8. CI-driven verification would need xvfb + a working WebKit
  in headless mode and is out of scope for this release.

### Stats

- 52 automated tests (44 `omux` + 8 `omux-hook` integration).
- `cargo build --release` produces a ~5.4 MB `omux` binary and a
  ~452 KB `omux-hook` helper, dynamically linked against system
  GTK4 / libadwaita / WebKitGTK 6 / VTE 4 / SQLite.
